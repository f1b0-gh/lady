# Container runtime security corrections

This is a scoped security update and a missing runtime dependency fix, not a
package-count reduction or a complete OS security qualification. The correction was recorded on 2026-11-15. Nixpkgs remains at
`1c89083e451e891152365b799595cf7790a43325`; Nickel remains at 1.18.0.

## Sources and build inputs

`container-security.nix`, `security-go.nix` and `locks/*.go.{mod,sum}` share the
corrections across minimal/debug builds. The upstream application code is
retained. Nix regenerates a vendor tree from each retained Go lock and verifies
its fixed hash. It never downloads a different compiler automatically.

| Component | Source | Change |
| --- | --- | --- |
| Skopeo | 1.25.1, commit `1fb351f23dbde474416ba33c3786a8d04304429b` | Added to bootc-base: ostree-ext invokes it as the image importer |
| Podman | 6.2.0, commit `055de046937d29450f310fce0fe3071485d8bed9` | Replaces 6.1.4 in both variants |
| Go | 1.26.11, official source SHA-256 `d44101b0ff27ed2a4c75ad46c17b9c74359209e2eb2ca7c9df6cb4fdb68e1969` | Replaces 1.26.10 for these runtime binaries |
| runc | 1.5.3, commit `46365c62967c76a765a5e347f48f0c7b3b571fe9` | Debug only; restore security fix and corrected Go locks/compiler |
| crun | Official 1.31 release tarball, commit `a84965e1278d08d6c75d5b8a41a3e72a7a11fa5b` | Both variants; restore and mount security fixes |
| CRIU | 4.3.1, commit `3ce556b7e8291c1bfdca974962f6282d7802b69f` | Debug only; external mount key fix |

The Go recipe reuses the pinned Nixpkgs bootstrap and platform patches.
Podman retains Nixpkgs' mac-helper packaging patch and runtime helper paths.
The completion fix is already upstream in 6.2.0 and is not applied twice.
The runtime-path patch runs after the regenerated vendor is installed, so
regeneration cannot discard it. Skopeo's default policy file comes from its new
source; the OS policy remains the explicit policy generated by `podman.nix`.
No new network permissions or daemon are enabled.

Both Podman/Skopeo locks update go-jose/v4 to 4.1.9, x/net to 0.62.0,
and the OpenTelemetry API/metric/trace family to 1.47.0. Its new log dependency
is retained at 1.47.0. The runc lock updates cilium/ebpf to 0.22.0,
moby/sys/user to 0.4.1 and x/net to 0.62.0; x/sys advances to 0.49.0 and
the Go directive to 1.26.0 as required by that dependency graph.
Optional dependencies and non-Linux platform modules are not removed to
improve inventory counts.

The latest upstream stable releases were reviewed. Go 1.27.4 is newer, but
1.26.11 supplies the security fix on the existing compiler branch, avoiding an
unrelated compiler migration. moby/sys/user 0.5.0 is newer, but 0.4.1 supplies
the fix on the applications' existing pre-1.0 API line. Revisit these choices at
the maintenance deadline below. go-jose 4.1.9 includes subsequent compatible
RSA/curve and OpaqueSigner fixes and is selected instead of the minimum 4.1.6.

crun uses the official release archive with bundled submodules. Nixpkgs' native
test selection and helper paths remain in place. Minimal crun still disables
CRIU and libkrun. CRIU 4.3.1 already contains both pinned Nixpkgs compatibility
patches (reverse dry-run applied successfully), so they are not applied twice.

OSV querybatch was run on every versioned vendored module in all three source
trees, with no platform filtering, plus the selected Go standard library and the three application root modules.
It is a module-version lookup, not a reachability analysis. Candidate and final
responses, UTC timestamps, vendor SHA-256 values and the bounded query script
are retained in the local sibling report directory
`nickeling/docs/bootc-podman/2026-11-15` (relative to the common checkout parent).
This cross-repository evidence location is not independently distributable.

Two module-level results remain visible: docker/distribution
GHSA-685w-q87j-wqw3 / GO-2026-6778 targets `registry/client`, while the
vendor trees include only `registry/api/{v2,errcode}`; x/crypto GO-2026-5932
targets the deprecated `openpgp` packages, which none of these vendors contains.
This exclusion is based on the delivered package set, not on an assertion that
the old module versions are globally safe. No exploitability experiment was run.

Coverage is incomplete for other native libraries, kernel, firmware and build
or test tools. Those remaining components are not cleared by this review.
Fresh advisory checks are required before a release; these files do not claim
that an online advisory gate or whole-repository alignment CI is qualified.

and corrected module sets by application context, with source-vendor hashes.
The original set contains Podman and debug runc; adding Skopeo changes scope.
This intentionally blocks any unchanged-scope/non-regression claim.

Compared with the original image this is +4 identities, +7 exact pairs,
+3 multiversion families and +3 excess versions. The Skopeo 1.24.1 closure probe
added one native output (~34 MB of regular files) and reused the existing native

New or changed divergent families are go-winio, protobuf-go-lite, go-criu/v8,
godbus/dbus/v5, go-multierror, pgzip, image-spec, mpb/v8, moby/sys/capability, x/sys and grpc.
Exact versions/contexts are in the retained sets. They follow the upstream
release locks; this work does not force unrelated alignment or modify upstream
code to reduce a counter. These differences require review and are not an
automatically renewed baseline or a blanket exception.

Maintenance owner: Ladyboot maintainers. Cost: three additional Go lock pairs,
one compiler override, three native source overrides, source/vendor hashes, targeted tests and renewed advisory
review. Reassess before release or by 2026-12-15, whichever comes first. Remove
these overrides only after an explicit catalogue migration supplies the fixes
and the runtime tests pass. Do not silently regenerate the reference or extend
this exception indefinitely. Existing unrelated debt remains backlog.

## Reproduction and limits

Normal `nix build` of the documented Podman outputs reconstructs the corrected
runtime from the retained sources/locks and validates vendor hashes. Nix uses
one build and two cores. The compiler itself is built from source.
To regenerate a lock intentionally, unpack the corresponding pinned source in
a new directory outside the flake, then use the `security-go.nix` compiler with
`GOTOOLCHAIN=local`, `GOMAXPROCS=2` and `GOFLAGS=-mod=mod`:

```
# Podman and Skopeo, separately:
go get github.com/go-jose/go-jose/v4@v4.1.9 golang.org/x/net@v0.62.0 go.opentelemetry.io/otel/trace@v1.47.0
go get go.opentelemetry.io/otel@v1.47.0 go.opentelemetry.io/otel/metric@v1.47.0
go mod vendor
# runc, separately:
go get github.com/cilium/ebpf@v0.22.0 github.com/moby/sys/user@v0.4.1 golang.org/x/net@v0.62.0
go mod vendor
```

Review every go.mod/go.sum change and hash the resulting vendor tree with
`nix hash path`. No project program is executed by these lock operations.
`../tests/test_go_runtime.py` reads the delivered Go ELF metadata, including wrapped
binaries, and rejects the old compiler or corrected-module versions. This
checks the actual artifact, not merely the recipe declarations. Compilation,
rootfs checks, rootless runtime, network and full bootc lifecycle are separate
gates; their latest status is recorded in the qualification report.

The test-only `../tests/go-buildinfo.go` reads the bounded `.go.buildinfo` ELF section
with `debug/elf` and parses its module text with `runtime/debug`. The pinned
Go 1.26.11 `debug/buildinfo.DataReader` tests `Filesz-1` without excluding
zero-sized segments; a GNU_STACK header moved before LOAD by patchelf causes
an unsigned underflow and a false “not a Go executable” for Podman. The
section reader avoids that lookup, without changing the delivered ELF.
Its result is checked against the native Go reader on Quadlet; truncated and
non-Go inputs must fail. This helper is never included in the runtime.
